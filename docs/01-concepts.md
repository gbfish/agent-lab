# 01 · 概念:什么才算 Agent

---

## 一句话

**普通 LLM 调用是一次性问答,Agent 是一个循环。**

```
目标 → 规划 → 调用工具 → 观察结果 → 再规划 → …… → 完成
```

区别在于**会不会动手**。Chatbot 只能「说」,Agent 能「做」——读文件、跑命令、查数据库、调 API。让它能动手的机制是 tool use / function calling,MCP 是把这些工具标准化描述出来的协议。

---

## 四个必要组件

| 组件 | 作用 | 本项目对应 |
|---|---|---|
| **模型** | 做决策的大脑 | Ollama 上的本地模型 |
| **工具** | 能产生副作用的手 | Goose 内置 `developer` extension(shell + 文件读写) |
| **记忆 / 状态** | 跨轮次保留上下文 | Goose session |
| **循环控制 + 终止条件** | 什么时候停、失败怎么办、谁批准高风险动作 | Goose 的权限模式 |

**最后一条最容易被忽略,但恰恰是工程上最难的部分。**

---

## 三个常见误判

### 「我跑了本地 LLM + WebUI,这算 Agent 吗?」
**不算。** 那是推理 + 界面。

- 本地模型 = 大脑
- WebUI = 人机界面,负责送输入、渲染输出
- **缺的是工具、循环、状态**

你打字 → 模型生成 → 结束。它不会自己决定「我需要先查一下手册」,也不会拿到结果后再想一轮。**没有循环,就不是 Agent。**

### 「我挂了一个检索工具,这算 Agent 吗?」
**还不算。** 如果每次都是「问 → 检索一次 → 回答」,那是 **RAG 流水线**,路径是你写死的。

### 分水岭在哪
> **模型看完第一次检索结果,能不能自己判断「证据不够,换个关键词再搜一遍」?**
>
> **决策权在模型手里而不在你的代码里,这才是 Agent。**

---

## 本项目要跨的那条线

不算 agent:
```
用户说「修好 buggy.py」 → 模型吐一段改好的代码 → 结束        [ 聊天 ]
```

算 agent:
```
用户说「修好 buggy.py」 → 模型读文件 → 改 → 跑一遍 → 看输出
       → 不对再改 → 对了才汇报                              [ Agent ]
```

分水岭就是 `evals/tasks.jsonl` 里 t07 那条:**它跑完之后有没有自己再跑一遍确认。** Goose 已经提供了循环,我们要测的是本地模型撑不撑得住这个循环。

**同时这也是所有麻烦的来源** —— 多轮循环意味着每一轮的工具调用都可能失败,失败率会累积。这就是为什么要先做基线测试,见 `05-eval-plan.md`。
