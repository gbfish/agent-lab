## 买了会改变什么

### ✅ 1. 模型档位跳一级,环 1/环 2 的坑基本填平
**这是最实质的改变。**

当前痛点是 14b 模型可能把 tool call 吐成裸文本导致循环崩溃——那是 7B–14B 区间的典型病。**128GB 能舒服跑 70B 级别,量化后甚至能碰 100B+。到那个体量,结构化工具调用基本是稳的。**

推论:Code mode 那个对策可能就不需要了。

### ✅ 2. prompt processing 快 3.9 倍,正中 RAG 痛点
Agent 每轮都把整段历史 + 工具返回(文件内容、命令输出,动辄几千 token)重新喂一遍,开销全在 prefill 阶段——正好是 M5 提升最大的地方。以后接检索类工具时更明显。

### ✅ 3. on-prem 的商业故事成立
苹果的说法是「完全隐私地在本机跑大模型,不用数着 token、也不担心云成本上涨」。

对数据不出厂的场景,这句话就是销售话术。一台 $2,499 的机器摆在厂里 vs 每月付 API 费用,ROI 表很好算。

## 不会改变什么

### ❌ 工具输出质量
工具返回的错误文本模型读不懂、提示词没让它纠错,再大的模型也救不了。**环 4 的锅硬件一点都背不动。**

### ❌ Harness 选择
Goose 还是 Goose。

### ❌ Agent 架构
循环怎么设计、权限怎么控、终止条件怎么定,全是软件问题。

### ❌ 你的差异化
硬件让你跑得动更好的模型——但**全世界买得起 $2,499 的人都能跑**。壁垒还是 HVAC 文档、技师真实问法、eval 集。

---

## 建议

### 不要买 M5 Ultra
512GB 是给「本机跑 frontier 级模型」准备的。本项目场景是 70B 级 agent,**M5 Max 128GB 完全够,差三千美元**。

集群那个功能听起来很酷,但那是给视频/VFX/大规模推理准备的,不是给一台本地 agent。

### 决策依据 = 失败分布表

| 测试结果 | 决定 |
|---|---|
| 工具调用正确率 ≥ 90% | **别买。** 瓶颈不在模型,去修软件问题 |
| 70–90% | 先免费试 Code mode 和提示工程,不行再买 |
| < 70%,且环 1/2 占多数 | **买 M5 Max 128GB,理由充分** |
| 失败集中在环 4 | **别买。** 改工具输出 / 提示词 |
